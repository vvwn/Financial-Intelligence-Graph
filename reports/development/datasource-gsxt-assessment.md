# 国家企业信用信息公示系统（gsxt）可用性评估 + 年报子公司表实测

> 调查时间：2026-11-13 21:05–21:35 · 调查方：`architect`
> 结论：**gsxt 用不了（也不需要用）**；巨潮年报附注里的子公司表已经覆盖了股权层。

---

## 一、gsxt 的结论

### 1.1 技术上被主动拦截

```
GET https://www.gsxt.gov.cn/index.html      → 521
GET http://www.gsxt.gov.cn/index.html       → 521
GET https://www.gsxt.gov.cn/corp-query-homepage.html → 521

响应体（884 字节）：
<script>document.cookie=('_')+('_')+('j')+('s')+('l')+('_')+('c')+('l')+('e')+('a')+('r')+...
```

这是**瑞数（Riverse）反爬**：返回 521 + 一段混淆 JS，要求浏览器执行后算出
`__jsl_clearance_s` cookie，通常还要再过一层验证码。

**我不做绕过。** 它属于主动的访问控制，绕过它等于规避对方明确设置的防线；
而且这类方案极其脆弱——对方一改算法就得重做，不适合作为长期数据管道。

### 1.2 就算拿到，也没有供应链数据

gsxt 提供的是**工商登记信息**：

| 有 | 没有 |
|---|---|
| 企业基本信息（统一社会信用代码、法定代表人、注册资本、经营范围） | **客户** |
| 股东及出资信息 | **供应商** |
| 主要人员 | **采购/销售金额** |
| 分支机构 | 任何交易关系 |
| 对外投资 | |
| 年报（资产状况、社保人数） | |

**它解决的是「这家公司是谁、谁持有它」，不是「它和谁做生意」。**

### 1.3 那它还有什么用？

只有一个场景是巨潮覆盖不到的：**向上穿透非上市股东**。
比如「某上市公司的控股股东是一家非上市公司，那家公司又被谁控股」——
这一段只有工商登记能查。

但这属于**股权穿透**，不是供应链，而且：
- 上市公司年报的「控股股东情况」章节通常已经说明了实控人
- 真要做穿透，合规路径是买企查查/天眼查的 API，而不是硬爬政府站点

**结论：P1/P2 不需要 gsxt。**

## 二、但发现了更好的东西：年报里的子公司表

查 gsxt 的过程中，在巨潮年报里发现了它的替代品——**附注「在其他主体中的权益 → 企业集团的构成」**。

### 2.1 数据长这样

中际旭创 2025 年年度报告（第 199–200 页）：

```
子公司名称   注册资本        主要经营地  注册地  业务性质        持股比例   取得方式
苏州旭创     2,834,600,000   苏州       苏州    设计、研发及生产   100.00%   合并
储翰科技     103,000,000     成都       成都    设计、研发及生产    99.74%   合并
深度智冷     100,000,000     广东       广东    设计、研发及生产    51.00%   设立
TeraHop Pte  228,000,000美元 新加坡     新加坡  投资、贸易及服务    67.71%   设立
...
```

**具名、有持股比例、有取得方式、有注册地——比 gsxt 更完整，而且不用绕过任何防线。**

### 2.2 已落地

新增：

| 文件 | 作用 |
|---|---|
| `app/collectors/cninfo_collector.py` | 巨潮公告检索 + PDF 下载（orgId → 公告列表 → PDF） |
| `app/extractors/annual_report.py` | 从「企业集团的构成」表抽取子公司与持股比例 |
| `app/extractors/pdf.py` | PDF 文本抽取 |
| `scripts/import_subsidiaries.py` | 一条命令：下载 → 抽取 → 建实体 → 建边 → 建证据 |

实测（中际旭创 300308）：

```
report: 2025年年度报告 (2026-03-30)
text chars: 207863
parsed rows: 26 (clean 26, needs review 0)
edges created: 26
projection: nodes=94 edges=80; consistent=True
depth=1 → nodes 28 edges 27，证据等级 {A: 26, B: 1}
```

证据示例：

```
type: annual_report | grade: A
title: 2025年年度报告
url:   http://static.cninfo.com.cn/finalpage/2026-03-31/1225056459.PDF
excerpt: [2025年年度报告 · 在其他主体中的权益] 苏州旭创 2,834,600,000 苏州 苏州
         设计、研发及生产 100.00%
```

点开 PDF 翻到第 199 页就能核对。

### 2.3 抽取器的已知限制

PDF 表格列会被打散，跨行的英文名（`TeraHop` / `Pte`）可能被拆开。处理方式：

- 能合并的合并（`TeraHop` + `Pte`）
- 合并不了的**标记 `needs_review`**，绝不当作干净名称入库
- 合计行、比例表行（`合计`、`及服务`、`应收单位`）用停用词 + 注册资本下限过滤

实测 26 行全部干净，0 条待复核。

## 三、巨潮 + gsxt 联合查询：我的判断

| 维度 | 判断 |
|---|---|
| 技术可行性 | ❌ gsxt 有瑞数反爬，不绕过 |
| 数据互补性 | 🟡 gsxt 只补「非上市股东穿透」，不补供应链 |
| 替代方案 | ✅ 巨潮年报的子公司表已覆盖上市公司股权层，且是 A 级证据 |
| 建议 | **不接 gsxt**。需要穿透时走合规付费 API |

**真正缺的仍然没变**：商业客户/供应商的具名关系。这一块公开数据拿不到，
gsxt 也给不了，只能等付费数据源或人工调研。

## 四、当前数据源全景

| 来源 | 提供 | 状态 |
|---|---|---|
| Baostock | 公司代码/名称/上市日期/证监会行业 | ✅ 已接入（51 家） |
| 巨潮 · 年报子公司表 | 子公司名称 + 持股比例 | ✅ 已接入（中际旭创 26 家） |
| 巨潮 · 关联交易公告 | 具名交易对方 + 金额 + 期限 | ✅ 已接入（太极实业→SK海力士） |
| 巨潮 · 年报前五名客户/供应商 | 金额 + 占比（**匿名**） | ⬜ 未接入（只能做集中度指标） |
| gsxt | 工商登记（股东/对外投资/分支机构） | ❌ 不接入（反爬 + 不含供应链） |
| 付费供应链数据 | 客户/供应商图谱 | ⬜ 待决策 |

图规模：**94 节点 / 80 边**，`reconcile consistent=True`。

## 五、下一步建议

1. **批量跑子公司抽取**：对 51 家公司逐个跑 `import_subsidiaries.py`，预计能建 300–800 条股权边（全部 A 级）
2. **抽「前五名客户集中度」**：不建边，作为 `entity.attributes.customer_concentration`，能回答「是否依赖单一大客户」
3. **不要接 gsxt**
4. 供应链关系仍待付费数据源或人工调研

要我现在批量跑第 1 项吗？跑完 51 家大概需要 15–25 分钟（每份年报 5–10MB，下载 + 解析）。
