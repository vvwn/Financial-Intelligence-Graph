## 二、核心结论：没有供应链数据

Tushare 全部接口里**没有**「前五大客户」「前五大供应商」「供应商图谱」这类数据。
它提供的是**公司属性**（属于哪个行业、卖什么产品、股东是谁），不是**公司之间的关系**。

所以：

- ❌ 不能解决「A 供货给 B」的具名边问题
- ✅ 能解决「这家公司到底做什么、属于哪个行业」的问题

## 三、它实际解决了什么：产业归属从「我判断」变成「有出处」

### 3.1 之前的问题

`belongs_to_industry` 边之前的证据是：

```
[Baostock 证监会行业分类] 中际旭创 归属 C39计算机、通信和其他电子设备制造业；
本项目产业划分：光模块。划分依据：800G 数通光模块
```

证监会分类只到 `C39` 这一级，「属于光模块」是**我的判断**，证据里也如实标了
`classification_source: project_taxonomy`。这不够硬。

### 3.2 现在

新增一条证据（`evidence_grade=B`）：

```
申万三级：通信网络设备及器件（通信 / 通信设备）；
主营构成（20251231）：光通信收发模块 374.57 亿元，占 97.95%；
公司主营业务：电机绕组制造装备的研发…光模块生产、销售业务
```

**「光通信收发模块占营收 97.95%」是公司自己披露的数据**，不是我猜的。

现在这条边有两条独立证据：证监会分类 + 申万分类与主营构成。

### 3.3 落地情况

```
universe: 51 companies
申万分类命中: 51/51
enriched: 51
```

每家公司的 `entity.attributes` 现在带：

```json
{
  "sw_l1": "通信", "sw_l2": "通信设备", "sw_l3": "通信网络设备及器件",
  "revenue_mix": [{"item": "光通信收发模块", "sales": 37456520000, "share_pct": 97.95}, ...],
  "main_business": "电机绕组制造装备的研发、设计、生产和销售,光模块生产、销售业务"
}
```

脚本：`scripts/enrich_classification_tushare.py`（`--dry-run` / `--apply`）
采集器：`app/collectors/tushare_collector.py`

## 四、一个重要的建模发现：行业分类 ≠ 产业链归属

对比申万分类和本项目的 AI-COMPUTE 划分，出现了系统性分歧：

| 公司 | 本项目划分 | 申万三级 | 说明 |
|---|---|---|---|
| 中际旭创 300308 | AI-COMPUTE-OPTICAL | 通信网络设备及器件 | 基本一致 |
| 立讯精密 002475 | AI-COMPUTE-CONNECTOR | **消费电子零部件及组装** | 主业是消费电子，AI 连接器是增量 |
| 沪电股份 002463 | AI-COMPUTE-PCB | 印制电路板 | 一致 |
| 润泽科技 300442 | AI-COMPUTE-IDC | 通信应用增值服务 | 近似 |

**这说明两件事是不同的维度**：

- **行业分类**（申万/证监会）= 公司主业归哪个行业，互斥、全覆盖
- **产业链主题归属**（AI 算力链）= 公司是否参与某条产业链，**不互斥、可跨行业**

立讯精密就是典型：申万把它归消费电子，但它在 AI 算力链里做高速连接器。
两者都对，只是问题不同。

**建议**：把 `belongs_to_industry` 的 `attributes.taxonomy` 明确写成
`thematic_chain`（本项目）或 `sw_industry`（第三方），不要让读者误以为
「AI-COMPUTE-OPTICAL」是行业分类。前端展示时也应该分开呈现。

## 五、结论与建议

| 问题 | 结论 |
|---|---|
| Tushare 能拿到数据吗 | ✅ 能，token 有效，主要接口可用 |
| 有供应链关系吗 | ❌ **没有**，和其他公开源一样 |
| 值得接入吗 | ✅ 值得——它把产业归属的证据从「项目判断」升级为「申万分类 + 公司披露主营构成」 |
| 要不要买更高积分 | 🟡 只有当你需要同花顺概念板块（`ths_member`）时才有必要；那也只是概念标签，不是供应链 |

**供应链关系仍然只能靠**：
1. 巨潮关联交易公告（已接入，覆盖关联方）
2. 付费供应链数据（企查查/Wind，待决策）
3. 人工调研
