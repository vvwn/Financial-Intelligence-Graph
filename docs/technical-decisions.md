## 已决策

### ADR-0001 · PostgreSQL 为唯一事实源，Neo4j 为派生投影

- **状态**：Accepted（2026-11-12）
- **背景**：需要同时用关系型库（审计、状态机、复杂约束）与图库（多跳遍历）。双写必然不一致。
- **决策**：所有写入只落 PG。Neo4j 由 `GraphProjector` 单向投影，可清空重建。
- **后果**：
  - ✅ 图可重建 = 可修复 = 可回滚；杜绝「多 Agent 同时写图」
  - ⚠️ 投影器成为单点，必须监控；图有秒级延迟
- **否决方案**：Neo4j 为主库（历史/审计弱）；PG+Neo4j 双主（一致性不可控）

### ADR-0002 · Python 版本锁定 3.12

- **状态**：Accepted（2026-11-12）
- **背景**：本机为 3.13.14，部分 C 扩展轮子覆盖不全。
- **决策**：容器与文档统一 3.12；本地建议 pyenv 装 3.12。
- **后果**：⚠️ 需确认 3.12 已安装，否则容器内验证前无法本地跑测试
- **待办**：TASK-601 在镜像中验证 3.12 依赖全部可装

### ADR-0003 · Claim / Evidence / VerifiedRelationship 三层分离

- **状态**：Accepted（2026-11-12）
- **背景**：模型输出极易被当成事实。若只有一张 relationship 表靠 status 区分，代码里一个 `UPDATE status` 就能把幻觉洗白。
- **决策**：三张独立表。Claim 提升为 Relationship 必须过 `state_guard`，且 `claim_type` 必须为 `fact_reported`。
- **后果**：
  - ✅ 幻觉无法通过单条 SQL 变成事实
  - ⚠️ 写入链路变长（多一次状态迁移），需在 UI 上把「候选」与「已验证」明确区分
- **否决方案**：单表 + status（否决：约束太弱）

### ADR-0004 · LLM 只能经 `LLMClient` 协议访问

- **状态**：Accepted（2026-11-12）
- **决策**：业务代码禁止直接 import 厂商 SDK；统一协议支持 provider 切换、录制回放、token 计量。
- **后果**：✅ 可换模型、可离线测；⚠️ 抽象层需自己维护，不能直接用厂商 SDK 的高级特性

### ADR-0005 · 调度用 APScheduler，不引 Prefect（初期）

- **状态**：Accepted（2026-11-12）
- **决策**：单进程定时任务足够；>50 个带依赖 DAG 时再评估。
- **后果**：⚠️ 多实例部署会重复执行，必须单 worker（技术债 D-05）

### ADR-0006 · 不做微服务

- **状态**：Accepted（2026-11-12）
- **决策**：模块化单体。包边界清晰，需要时再拆。
- **后果**：✅ 事务简单、调试简单；⚠️ 单进程成为扩展瓶颈（P5 前不是问题）
