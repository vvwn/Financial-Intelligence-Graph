# 开发路线图与验收标准

> 版本 v0.1 · 2026-11-12 · 维护者：`architect`

---

## 里程碑总览

| 阶段 | 目标 | 门禁 | 预估任务数 |
|---|---|---|---|
| **P0** | 架构、契约、可行性 | 架构评审报告通过 | 7 |
| **P1** | 能跑的产业图谱底座 | 能查公司、上下游、证据，重启不丢 | 10 |
| **P2** | 采集 + AI 自动扩展 | 一条真实新闻跑出候选关系与证据 | 8 |
| **P3** | 质量控制与纠错 | 25 个注入错误检出率 ≥ 80% | 5 |
| **P4** | Web 工作台 | 浏览器内完成七类操作 | 4 |
| **P5** | 投资研究 | 事件影响评分 + 回测复盘 | 3 |

**硬规则：前一阶段验收未通过，不进入下一阶段。** 不允许「一边做 P2 一边补 P1」。

## Phase 1 · 知识图谱底座

**范围**：AI 算力产业链，50–100 家 A 股公司，12 个细分产业。

**任务**：实体库、产业分类、基础关系、证据表、关系状态、Neo4j 查询、PG 持久化、基本图谱 API。

**验收**

- [ ] 能按股票代码/名称查公司
- [ ] 能查某公司的上下游（含关系类型与方向）
- [ ] 每条关系能展开看证据（来源、摘录、等级）
- [ ] 已验证 / 待核验关系在结果中可区分
- [ ] 重启服务后数据仍在
- [ ] 清空 Neo4j 后可从 PG 完整重建，差异为 0
- [ ] 能做基础历史追踪（某关系何时建立/变更）

**不做**：新闻采集、AI 推理、前端（除 Mock 原型）。

---

## Phase 2 · 采集与 AI 关系扩展

**验收**（用一条真实新闻，端到端）

- [ ] 系统自动识别事件类型与重要性
- [ ] 提取关键实体，并正确链接到已有实体（不新建重复实体）
- [ ] 找到与图谱的连接点
- [ ] 生成候选关系（Claim），每条带证据引用
- [ ] 证据不足的关系进入 `pending_verification`，**不进图**
- [ ] 输出事件影响路径（含方向、周期、置信度、不确定因素）
- [ ] 同一新闻多家转载只算 1 条独立证据

**不做**：正式关系审批（人工/规则）、前端页面。

---

## Phase 3 · 质量控制与自动纠错

**验收**

- [ ] 植入 25 个错误，检出率 ≥ 80%，误报率 ≤ 20%
- [ ] 每个命中附定位依据（rule_id + 证据）
- [ ] 撤销一条错误关系 → 识别受影响传导路径 → 重算 → 输出 diff
- [ ] 七项质量指标可从真实数据算出
- [ ] 非法状态迁移被 state_guard 拦截（含 `inferred` 提升）

**这是项目最核心的阶段。** 质量中心做不好，后面全是漂亮垃圾。

---

## Phase 4 · Web 工作台

**七类页面**：情报总览 / 产业图谱 / 全球事件 / 投资机会 / 质量中心 / 历史复盘 / 系统管理。

**验收**

- [ ] 浏览器内可搜索产业、搜索公司
- [ ] 可浏览上下游、点击关系看证据
- [ ] 可局部扩展图谱（带 truncated 提示）
- [ ] 可查看事件影响路径与关联股票
- [ ] 可发现待核验关系并处理
- [ ] 可追踪历史变化（某关系何时建立、何时修正）
- [ ] 首屏 ≤ 300 节点，交互 60fps

---

## Phase 5 · 投资研究

**验收**

- [ ] 接入财务、估值、行情数据
- [ ] 事件影响评分（产业景气 → 公司受益程度 → 预期差）
- [ ] 历史事件回测：给定过去事件，系统当时会给出什么结论，实际结果如何
- [ ] 预测结果可复盘，误差可归因
- [ ] **投资判断与产业事实严格分离**，不把分析包装成确定性建议

---

## 阶段间门禁（不可跳过）

```
P0 评审通过
  → P1 验收（图谱能查、能重建）
    → P2 验收（一条新闻端到端跑通）
      → P3 验收（错误能检出、能纠错）
        → P4 验收（浏览器可用）
          → P5 验收（投资结论可复盘）
```

**每阶段结束时必须更新**：`project-status.md`、`task-board.md`、`changelog.md`、测试报告。
